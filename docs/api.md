# HTTP API contract (v0, may change)

Local Hono server on the laptop. Payload shapes are the zod schemas in `packages/schema`. Errors: JSON `{ "code", "text" }` with a 4xx/5xx status.

| Method | Path | Request | Response | Notes |
| --- | --- | --- | --- | --- |
| POST | `/api/login` | `{ user_id, pin }` | `{ token, role }` | Public. `401 invalid_credentials` otherwise. See Auth. |
| POST | `/api/sessions` | `{ id?, fiche_number?, facility? }` | Session (`page_ids: []`) | Midwife only. `id` (UUID) is optional: the phone creates it so a session can exist offline (without it the server generates one). Idempotent by id: a replay returns the stored session (its `page_ids`) and changes nothing; an id owned by another midwife is `409 session_id_taken`; a malformed id is `400 bad_request`. |
| POST | `/api/pages` | multipart: `meta` (RecordPage JSON, `id` = UUID created on the phone) + `image` (original file) | `200` RecordPage | Midwife only; `meta.midwife_id` must be the caller and `meta.session_id` one of her sessions (`404 session_not_found`). Idempotent by page id: a replay returns the stored page (its current state) and changes nothing. The server recomputes the SHA-256 and rejects (`409 sha256_mismatch`) a mismatch with `meta.sha256`. The image is stored encrypted, untouched; `meta.state` is ignored: the page is `CAPTURED`, then `PENDING_AI` once queued (with `ANALYZER=ink`: straight to `MANUAL_REVIEW_REQUIRED`, no model). **Retake**: `meta.replaces` (page id) = the phone captured the same page type again; the replaced page must be the caller's, in the same session and of the same `page_type` (`404 not_found` / `400 invalid_meta` otherwise); it gets the `SUPERSEDED` flag and leaves the review queue, the new page is analyzed as usual. |
| GET | `/api/pages/:id` | none | RecordPage + `fields: ExtractedField[]` | Owner midwife or supervisor (`403`/`404` otherwise). `fields` is empty until the analysis ran. |
| GET | `/api/sessions/:id/analysis` | none | NDJSON stream of analysis events (`page_received`, `page_read`, `field_flagged`, `record_ready`) | One JSON object per line, parsed with `parseEvent`. Replays the stored events of the session, then follows live. The stream never closes by itself (a session can receive more pages): it ends when the client disconnects. A `{"type":"ping"}` line is sent after 10 s without events. A page that fails produces the shared `error` event (`code`, `text` = `page <id> failed`, `page_id`), e.g. `page_type_required` (the phone must send `page_type`; template matching comes later), `page_type_unsupported`, `model_unreachable`/`model_http`/`model_timeout`, `analysis_failed`; the page is then `PROCESSING_FAILED`. `record_ready` (`record_id` = session id) is sent when no page of the session is still waiting for the analysis. Flow: `PENDING_AI` -> `AI_PROCESSED` -> `NEEDS_REVIEW`. `field_flagged` is sent for each `NEEDS_REVIEW`, `ILLEGIBLE` or `UNKNOWN` field. |
| PATCH | `/api/pages/:id/fields/:fieldId` | `{ confirm: true }` or `{ value, status? }` or `{ status: "ILLEGIBLE" }` | updated ExtractedField (+ `text_fr?`) | Midwife edit of her own page, while it is `NEEDS_REVIEW`/`MANUAL_REVIEW_REQUIRED` (`409 page_not_editable` otherwise); unknown field `404`; malformed body `400`. **confirm**: keeps the current value, status `KNOWN` (`400` when the field has no value). **correct** (`value` string/boolean/null, `status` absent or `KNOWN`): the value is PII-masked, normalized and validated like the model output; failing a validator keeps the field `NEEDS_REVIEW` (`reason: "corrected"`, `validators_passed: false`) and `text_fr` says why (« « 1700 » ne convient pas pour Taille (attendu : entre 120 et 200 cm). Le champ reste à vérifier. »); an empty value gives `NOT_PROVIDED`. **leave illegible** (`status: "ILLEGIBLE"`): value null, `reason: "left_illegible"`, the field leaves the review queue. Any other explicit `status` is stored as given. `text_fr` also reports a masked identifier. Audited (actor, role, old and new value+status, time) in all cases. |
| POST | `/api/pages/:id/manual` | none | RecordPage + `fields` | Midwife only, own page. Manual entry when the AI is unavailable: reads the page with ink only (no model): checkboxes from the ink (`KNOWN`), text cells without ink `NOT_PROVIDED`, text cells with ink `UNKNOWN` with `reason: "manual"` (to type). The page goes `PROCESSING_FAILED` (or `CAPTURED`) -> `MANUAL_REVIEW_REQUIRED`; `page_read` and `field_flagged` are published on the analysis stream. `409 page_not_failed` from any other state, `409 page_type_unsupported`/`page_type_required` when the page has no schema. |
| GET | `/api/sessions/:id/review` | none | `ReviewQueue` | Owner midwife or supervisor. `items`: the ordered queue of fields that need the midwife (pages in capture order, `SUPERSEDED` and closed pages skipped, fields in reading order, status `NEEDS_REVIEW`, `UNKNOWN` or `ILLEGIBLE` not kept illegible). Item: `{ page_id, field_id, kind: doubt\|illegible\|unread\|manual, label_fr, value, reason_code: unusual_value\|ink_but_empty\|illegible\|not_read\|manual, text_fr, actions }`; `actions` among `confirm` (only with a value), `correct`, `retake`, `leave_illegible`. `reason_code` comes from the stored signals (`validators_passed=false` -> `unusual_value`, `agreement=0` -> `ink_but_empty`). `progress`: `{ total, done, pages: [{ page_id, page_type, state, total, done }] }`, `total` = flagged fields still open + already reviewed (« 2/5 champs vérifiés »). |
| POST | `/api/pages/:id/confirm` | none | RecordPage | Moves the page to `VALIDATED` if the lifecycle allows it (`409 illegal_transition` otherwise); `409 fields_need_review` with `field_ids` while a field is still `NEEDS_REVIEW`. Idempotent when already validated. |
| GET | `/api/patients/candidates?fiche=&facility=` | query | `Candidate[]` | **Step 11, not implemented.** Looked up by `(fiche_number, facility)`. No personal identifiers are ever returned. |
| POST | `/api/sessions/:id/link` | LinkDecision | `Patient` or `{ status: "not_sure" }` | **Step 11, not implemented.** `create_new` allocates the next `PAT-000001...` from a server counter. |
| POST | `/api/chat` | `{ session_id, page_id?, field_id?, message }` | NDJSON stream of chat events (`token`, `ping`, `done`, `error`) | Midwife only. `message` 1..500 chars; `field_id` needs `page_id`; the page must belong to the session (`404`). The current item is the given field, else the head of the review queue (of `page_id` if given). The default engine is deterministic: it understands short French answers about the current item (a value: number with decimal comma/dot and optional unit, date d/m/yy(yy), blood pressure `120/80`, oui/non, neg/pos; « c'est bon » / « ok » / « oui c'est ça » = confirm; « je ne sais pas » / « illisible » = leave illegible; « reprendre » / « nouvelle photo » = a hint to use the retake button) and applies it through the same code as `PATCH` (a value that still fails a validator stays `NEEDS_REVIEW` and the reply says why). Anything else: « Je n'ai pas compris. Tapez la valeur, ou utilisez les boutons. » The French reply is streamed as `token` events, then `done`; an `error` event (`code`, `text`) ends the stream on failure. `ping` is sent every 10 s while the engine is slow. The message is PII-masked first and **never stored**: only the resulting field change (audited) is. `CHAT_ENGINE=strands` swaps in an LLM with record-scoped tools (see `docs/security.md`); the contract is the same. |
| GET | `/api/originals/:pageId` | none | original image bytes | Role-restricted: the `midwife` for her own patients' pages, the `supervisor` for all; every attempt (allowed or not, including unknown pages) is logged in `originals_access`; `403` when denied, `404` for an unknown page. `Content-Type` is sniffed from the bytes (PNG/JPEG). |
| GET | `/api/health` | none | `{ status: "ok", model: string \| null }` | Public on the local network. `model` is null when the analysis is off (`ANALYZER=off`). |

Conventions:

- Streams use `Content-Type: application/x-ndjson`, one event per line, no framing beyond the newline.
- Roles are `midwife` and `supervisor`. A midwife sees and modifies only her own sessions and pages; the supervisor sees everything and modifies nothing.

Auth (demo-grade, not for production: no token expiry, no rate limiting, no TLS):

- `POST /api/login` with `{ user_id, pin }` returns `{ token, role }`; the token is 32 random bytes (hex). Every other `/api/*` route except `/api/health` needs `Authorization: Bearer <token>` (`401 unauthorized` otherwise).
- Users are seeded on first start from `DATA_DIR/users.json` (`[{ "id", "role", "pin" }]`), else the demo set `sf-01`, `sf-02` (midwives) and `sup-01` (supervisor) with random 6-digit PINs printed once on the console. PINs are stored as scrypt hashes with a salt.
- `ExtractedField.reason` (optional): `manual` (text cell with ink to be typed), `corrected` (typed value still failing a validator), `left_illegible`.
- Other errors: `403 forbidden`, `404 not_found`, `400 bad_request`/`invalid_meta`.
