# HTTP API contract (v0, may change)

Local Hono server on the laptop. Payload shapes are the zod schemas in `packages/schema`. Errors: JSON `{ "code", "text" }` with a 4xx/5xx status.

| Method | Path | Request | Response | Notes |
| --- | --- | --- | --- | --- |
| POST | `/api/login` | `{ user_id, pin }` | `{ token, role }` | Public. `401 invalid_credentials` otherwise. See Auth. |
| POST | `/api/sessions` | `{ id?, fiche_number?, facility? }` | Session (`page_ids: []`) | Midwife only. `id` (UUID) is optional: the phone creates it so a session can exist offline (without it the server generates one). Idempotent by id: a replay returns the stored session (its `page_ids`) and changes nothing; an id owned by another midwife is `409 session_id_taken`; a malformed id is `400 bad_request`. |
| POST | `/api/pages` | multipart: `meta` (RecordPage JSON, `id` = UUID created on the phone) + `image` (original file) | `200` RecordPage | Midwife only; `meta.midwife_id` must be the caller and `meta.session_id` one of her sessions (`404 session_not_found`). Idempotent by page id: a replay returns the stored page (its current state) and changes nothing. The server recomputes the SHA-256 and rejects (`409 sha256_mismatch`) a mismatch with `meta.sha256`. The image is stored encrypted, untouched; `meta.state` is ignored: the page is `CAPTURED`, then `PENDING_AI` once queued (with `ANALYZER=ink`: straight to `MANUAL_REVIEW_REQUIRED`, no model). `meta.quality` (QualityResult from the on-device gate) and `meta.flags` (`LOW_QUALITY` when the midwife kept a warned photo) are stored as sent; with `LOW_QUALITY`, the analysis result of every `KNOWN` field is downgraded to `NEEDS_REVIEW` (`reason: "low_quality"`). Before the analysis the server rectifies the page in memory when it finds a page quadrilateral (the stored original is untouched). **Retake**: `meta.replaces` (page id) = the phone captured the same page type again; the replaced page must be the caller's, in the same session and of the same `page_type` (`404 not_found` / `400 invalid_meta` otherwise); it gets the `SUPERSEDED` flag and leaves the review queue, the new page is analyzed as usual. |
| GET | `/api/pages/:id` | none | RecordPage + `fields: ExtractedField[]` | Owner midwife or supervisor (`403`/`404` otherwise). `fields` is empty until the analysis ran. |
| GET | `/api/sessions/:id/analysis` | none | NDJSON stream of analysis events (`page_received`, `page_read`, `field_flagged`, `record_ready`) | One JSON object per line, parsed with `parseEvent`. Replays the stored events of the session, then follows live. The stream never closes by itself (a session can receive more pages): it ends when the client disconnects. A `{"type":"ping"}` line is sent after 10 s without events. A page that fails produces the shared `error` event (`code`, `text` = `page <id> failed`, `page_id`), e.g. `page_type_required` (the phone must send `page_type`; template matching comes later), `page_type_unsupported`, `model_unreachable`/`model_http`/`model_timeout`, `analysis_failed`; the page is then `PROCESSING_FAILED`. `record_ready` (`record_id` = session id) is sent when no page of the session is still waiting for the analysis. Flow: `PENDING_AI` -> `AI_PROCESSED` -> `NEEDS_REVIEW`. `field_flagged` is sent for each `NEEDS_REVIEW`, `ILLEGIBLE` or `UNKNOWN` field. |
| PATCH | `/api/pages/:id/fields/:fieldId` | `{ confirm: true }` or `{ value, status? }` or `{ status: "ILLEGIBLE" }` | updated ExtractedField (+ `text_fr?`) | Midwife edit of her own page, while it is `NEEDS_REVIEW`/`MANUAL_REVIEW_REQUIRED` (`409 page_not_editable` otherwise); unknown field `404`; malformed body `400`. **confirm**: keeps the current value, status `KNOWN` (`400` when the field has no value). **correct** (`value` string/boolean/null, `status` absent or `KNOWN`): the value is PII-masked, normalized and validated like the model output; failing a validator keeps the field `NEEDS_REVIEW` (`reason: "corrected"`, `validators_passed: false`) and `text_fr` says why (« « 1700 » ne convient pas pour Taille (attendu : entre 120 et 200 cm). Le champ reste à vérifier. »); an empty value gives `NOT_PROVIDED`. **leave illegible** (`status: "ILLEGIBLE"`): value null, `reason: "left_illegible"`, the field leaves the review queue. Any other explicit `status` is stored as given. `text_fr` also reports a masked identifier. Audited (actor, role, old and new value+status, time) in all cases. |
| POST | `/api/pages/:id/manual` | none | RecordPage + `fields` | Midwife only, own page. Manual entry when the AI is unavailable: reads the page with ink only (no model): checkboxes from the ink (`KNOWN`), text cells without ink `NOT_PROVIDED`, text cells with ink `UNKNOWN` with `reason: "manual"` (to type). The page goes `PROCESSING_FAILED` (or `CAPTURED`) -> `MANUAL_REVIEW_REQUIRED`; `page_read` and `field_flagged` are published on the analysis stream. `409 page_not_failed` from any other state, `409 page_type_unsupported`/`page_type_required` when the page has no schema. |
| GET | `/api/sessions/:id/review` | none | `ReviewQueue` | Owner midwife or supervisor. `items`: the ordered queue of fields that need the midwife (pages in capture order, `SUPERSEDED` and closed pages skipped, fields in reading order, status `NEEDS_REVIEW`, `UNKNOWN` or `ILLEGIBLE` not kept illegible). Item: `{ page_id, field_id, kind: doubt\|illegible\|unread\|manual, label_fr, value, reason_code: unusual_value\|ink_but_empty\|illegible\|not_read\|manual\|low_quality\|low_category_confidence, text_fr, actions, detail_fr? }`; `actions` among `confirm` (only with a value), `correct`, `retake`, `leave_illegible`. `reason_code` comes from the stored signals (`validators_passed=false` -> `unusual_value`, `agreement=0` -> `ink_but_empty`; `reason: "low_quality"` -> `low_quality`; `reason: "low_category_confidence"` -> `low_category_confidence`). `detail_fr` (optional, audit/jury, shown behind a « Détails » link) = « confiance estimée 91 % [86–94 %] sur 240 exemples », present only when the field has `calibrated`. `progress`: `{ total, done, pages: [{ page_id, page_type, state, total, done }] }`, `total` = flagged fields still open + already reviewed (« 2/5 champs vérifiés »). |
| POST | `/api/pages/:id/confirm` | none | RecordPage | Moves the page to `VALIDATED` if the lifecycle allows it (`409 illegal_transition` otherwise); `409 fields_need_review` with `field_ids` while a field is still `NEEDS_REVIEW`. Idempotent when already validated. |
| PATCH | `/api/sessions/:id` | `{ fiche_number?, facility? }` | `LinkProposal` | **Step 11.** Midwife only, own session. The midwife types or confirms the link key (the code written on the registry, the fiche number; the facility is optional); it wins over the cover reading (and a typed fiche is no longer treated as a doubtful reading). Each value 1..80 chars; a value that looks like a personal identifier (CIN, phone, e-mail, street) is `400`; `409 already_linked` once the session is linked. Returns the question asked again with the new key. |
| GET | `/api/patients/candidates?session_id=` or `?fiche=[&facility=]` | query | `LinkProposal` | **Step 11.** Read-only: nothing is created or linked. By session (own session, or any for the supervisor): the key is the typed fiche/facility of the session, else the cover reading (`p01.n_deg_de_la_fiche`, `p01.nom_de_l_etablissement_sanitaire`), and age (p02), DDR (p03), gravidity/parity (p02), province (p01) are cross-checked. By `fiche` (+ optional `facility`): the typed key, no cross-check. Without a facility the code alone decides (exact or one edit away; the facility and attribute matches need a facility on both sides; a patient created without facility matches any). `LinkProposal` = `{ session_id, fiche: { value, source: typed\|cover\|none, low_confidence }, facility, question, text_fr, candidates }`. `question`: `need_key` (no readable fiche: type it), `confirm_fiche` (doubtful reading: « J'ai lu 2O26-823-OO1, est-ce correct ? »), `propose` (exactly one exact and consistent candidate: one tap), `create` (no candidate: propose to create), `choose` (several, near or inconsistent: [Patient 1] [Patient 2] [Aucune, créer] [Je ne sais pas]). `candidates` (best first, at most 2) = `{ patient_id, score, kind: exact\|near_fiche\|near_facility\|near_attributes, consistent, reasons (French), summary: { fiche_number, facility, age?, ddr?, visits, last_visit? } }`: the summary holds no personal identifier. Every question asks; the server never links or creates by itself. |
| POST | `/api/sessions/:id/link` | LinkDecision: `{ kind: "patient", patient_id }` \| `{ kind: "create_new" }` \| `{ kind: "not_sure" }` | `LinkResult` = `{ status: linked\|not_sure, patient?, visits?, differences }` | **Step 11.** Midwife only, own session; every non-superseded page must be `VALIDATED` (`409 session_not_ready`). `patient`: links to an existing patient (`404 patient_not_found`). `create_new`: allocates the next `PAT-000001...` from a server counter (never derived from the data; `409 link_key_missing` without a fiche; a patient created without facility stores an empty one) after the decision. `not_sure`: pages go `DUPLICATE_SUSPECTED`, no patient is created or linked. The pages go `VALIDATED` -> `PATIENT_MATCHED` -> `REGISTERED` (persisted before the response). A parked session is settled later with the same endpoint (`patient` or `create_new`: `DUPLICATE_SUSPECTED` -> `PATIENT_MATCHED` -> `REGISTERED`); `not_sure` again changes nothing; any decision on a linked session is `409 already_linked`. `differences` = the re-digitization differences (see below), empty for a first visit. |
| GET | `/api/sessions/:id/redigitization` | none | `Difference[]` | **Step 11.** Owner or supervisor. When a session links to a patient who already has a page of the same type, each field whose retained (old) value is usable and that the new page changes (empty, unreliable, or another value) is a difference: `{ page_id, field_id, label_fr, page_type, old_value, old_date, new_value, choice: old\|new, decided }`. A field that was empty in the record and is filled by the new page is simply added (nothing to choose). Default `choice`: `new` when the new value is `KNOWN` and non-empty, else `old`; `decided` is false until the midwife chooses. Both pages stay stored. |
| PUT | `/api/sessions/:id/redigitization` | `{ choices: [{ page_id, field_id, choice: "old" \| "new" }] }` | `Difference[]` | **Step 11.** Midwife only, own session. « Garder l'ancien » / « Prendre le nouveau » per field; `404` for a field that is not one of the session's differences. The record view applies the choices at once. |
| POST | `/api/sessions/:id/ack` | none | `{ status: "SYNCED" }` | **Step 11.** Midwife only, own session. **SYNCED** = the phone acknowledged the registered record (it received the link result and showed it): `REGISTERED` -> `SYNCED`. `409 not_registered` unless every non-superseded page is `REGISTERED` (or already `SYNCED`: replay changes nothing). `SYNC_FAILED` keeps its existing edge to `REGISTERED`; no other state is added. |
| GET | `/api/patients/:id` | none | `PatientRecord` | **Step 11.** The longitudinal record: `{ patient: { id, fiche_number, facility, created_at }, visits: [{ session_id, date, pages: [{ page_id, page_type, captured_at, state }] }] (in link order), values: [{ page_type, field_id, label_fr, value, source_page_id, source_date }] }`. `values` = the retained non-empty value of each field (old or new according to the choices) with the page and date it comes from. A midwife gets it only for a patient she has linked a session to (`403 forbidden` otherwise); the supervisor sees all; unknown id `404`. |
| GET | `/api/stats` | none | `Aggregates` | **Dashboard (bonus).** Supervisor only (`403` otherwise). Anonymized counts per band over the `KNOWN` readings of pages that went through a link decision (`PATIENT_MATCHED` and later, retaken pages left out): systolic BP (`p03.ta`, `p05.ta`), temperature (`p05.t_deg`, `p06.temperature`), HIV, syphilis and Ag HBs results. `Aggregates` = `{ source: records\|reference, source_fr, blocks: [{ id, title_fr, note_fr?, n, bins: [{ label_fr, count }] }] }`. A count of 1 to 4 is hidden (`count: null`, shown « < 5 »). No patient id, session id, page id, field id or date in the answer. Not decision support: the bands are numeric ranges without a verdict. |
| GET | `/api/stats/reference` | none | `Aggregates` | Same shape from the synthetic reference CSV of the challenge (read-only under `DATASETS_DIR`, 200 women: systolic BP, HIV, syphilis, hepatitis C). Supervisor only; `404 no_reference` when the file is absent. |
| GET | `/api/review/duplicates` | none | `[{ session_id, midwife_id, decided_at, proposal: LinkProposal }]` | **Step 11.** Sessions parked by « Je ne sais pas » (`DUPLICATE_SUSPECTED`), with the candidates recomputed now. The supervisor sees all, a midwife her own. The supervisor reads; the owner midwife settles with `POST /api/sessions/:id/link`. |
| POST | `/api/chat` | `{ session_id, page_id?, field_id?, message }` | NDJSON stream of chat events (`token`, `ping`, `done`, `error`) | Midwife only. `message` 1..500 chars; `field_id` needs `page_id`; the page must belong to the session (`404`). The current item is the given field, else the head of the review queue (of `page_id` if given). The default engine is deterministic: it understands short French answers about the current item (a value: number with decimal comma/dot and optional unit, date d/m/yy(yy), blood pressure `120/80`, oui/non, neg/pos; « c'est bon » / « ok » / « oui c'est ça » = confirm; « je ne sais pas » / « illisible » = leave illegible; « reprendre » / « nouvelle photo » = a hint to use the retake button) and applies it through the same code as `PATCH` (a value that still fails a validator stays `NEEDS_REVIEW` and the reply says why). Anything else: « Je n'ai pas compris. Tapez la valeur, ou utilisez les boutons. » The French reply is streamed as `token` events, then `done`; an `error` event (`code`, `text`) ends the stream on failure. `ping` is sent every 10 s while the engine is slow. The message is PII-masked first and **never stored**: only the resulting field change (audited) is. `CHAT_ENGINE=strands` swaps in an LLM with record-scoped tools (see `docs/security.md`); the contract is the same. |
| GET | `/api/originals/:pageId` | none | original image bytes | Role-restricted: the `midwife` for her own patients' pages, the `supervisor` for all; every attempt (allowed or not, including unknown pages) is logged in `originals_access`; `403` when denied, `404` for an unknown page. `Content-Type` is sniffed from the bytes (PNG/JPEG). |
| GET | `/api/health` | none | `{ status: "ok", model: string \| null }` | Public on the local network. `model` is null when the analysis is off (`ANALYZER=off`). |

Conventions:

- Streams use `Content-Type: application/x-ndjson`, one event per line, no framing beyond the newline.
- Roles are `midwife` and `supervisor`. A midwife sees and modifies only her own sessions and pages (and the records of the patients she has linked a session to); the supervisor sees everything and modifies nothing.

Auth (demo-grade, not for production: no token expiry, no rate limiting, no TLS):

- `POST /api/login` with `{ user_id, pin }` returns `{ token, role }`; the token is 32 random bytes (hex). Every other `/api/*` route except `/api/health` needs `Authorization: Bearer <token>` (`401 unauthorized` otherwise).
- Users are seeded on first start from `DATA_DIR/users.json` (`[{ "id", "role", "pin" }]`), else the demo set `sf-01`, `sf-02` (midwives) and `sup-01` (supervisor) with random 6-digit PINs printed once on the console. PINs are stored as scrypt hashes with a salt.
- `ExtractedField.calibrated` / `calibration` (optional, step 13): category accuracy from the calibration table × the quality factor, and `{ low, high, n }` (Wilson 95 % interval × factor, sample size); set only on fields the analysis read as `KNOWN` while a table matching the pipeline was loaded (`docs/calibration.md`). Never shown as a percentage in the main UI.
- `ExtractedField.reason` (optional): `manual` (text cell with ink to be typed), `corrected` (typed value still failing a validator), `left_illegible`, `low_quality` (the page has the `LOW_QUALITY` flag: every field the analysis read as `KNOWN` becomes `NEEDS_REVIEW` with `confidence_signals.quality` 0.5), `low_category_confidence` (the calibration table puts the field's whole category under the 0.95 target: `KNOWN` becomes `NEEDS_REVIEW`).
- Other errors: `403 forbidden`, `404 not_found`, `400 bad_request`/`invalid_meta`. Linking (step 11): `409 session_not_ready`, `409 already_linked`, `409 link_key_missing`, `409 not_registered`, `404 patient_not_found`.
